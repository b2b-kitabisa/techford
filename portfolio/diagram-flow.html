Alur 1 — Lead masuk otomatis dari Typeform

Menggantikan rantai lama Typeform → Google Sheets → IMPORTRANGE → baca sheet, yang jadi salah satu sumber beban rate limit.
Eksternal
Typeform
Form inbound publik. Integrasi Google Sheets lama tetap jalan berdampingan.
⟶
Route Handler
/api/webhooks/typeform
Verifikasi HMAC-SHA256 atas raw body. Signature salah → 401, data tidak pernah masuk.
⟶
Normalisasi
Pemetaan jawaban
Cocokkan 8 pertanyaan ke kolom, baca hidden field UTM, rapikan nomor telepon.
⟶
Postgres
Tabel lead
Inbound ID di-generate atomik. response_id unik → kiriman ulang tidak menggandakan data.
⟶
Aplikasi
Lead Capturing
Muncul dalam hitungan detik, lengkap dengan deteksi duplikat email/telepon.

Alur 2 — Approval COR tanpa login

Approver (Head of B2B) sering menyetujui dari ponsel. Link bertoken menghapus friksi login tanpa mengorbankan kontrol.
Consultant
Request Approval
Margin guard dievaluasi ulang di server — bukan dari angka yang tampil di layar.
⟶
Server Action
Token + email
UUID acak, masa berlaku 14 hari, dikirim via SMTP ke approver.
⟶
Approver
Buka link
Halaman GET hanya menampilkan ringkasan — tidak pernah mengubah status.
⟶
Server Action
POST Approve / Reject
Tiga gerbang: token tidak ditemukan · sudah dipakai · kedaluwarsa — masing-masing pesan berbeda.
⟶
Efek
Status + snapshot
Budget snapshot & audit log ditulis best-effort: gagal pun tidak membatalkan approval.
Prinsip yang dipegang di seluruh alur
Semua perubahan status melewati Server Action yang memvalidasi ulang kondisinya di server. Di platform lama, sebagian aturan hanya dijaga di sisi browser — sehingga status bisa melompat kalau seseorang memanggil fungsi yang salah. Di v2 hal itu tidak mungkin: browser tidak punya kunci database, dan setiap transisi memeriksa state saat itu juga sebelum menulis.

Alur 4 — Dari Lead sampai Uang

Rantai utama yang dijaga platform ini.
1

2
